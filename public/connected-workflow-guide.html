Omni → Workflow

Automatic syncOrder snapshots update customer details, payments, freight routing and packing indicators. Shipping jobs belong on Delivery; collection jobs belong on Collect.

Workflow → Omni

Open Omni + SaveFull delivery/collection sets Dispatched and its date/time. Reversing completion restores readiness; unchecking packing restores New. Keep the matching order open with the script running and save the changed Omni fields.

Omni + Workflow → HubSpot

Background syncSaved order information and saved Workflow actions determine the deal stage. Won is a Status value, not the same thing as Completed.

Workflow → WeCom

NotificationsBooking and work events notify the configured rep / warehouse / delivery / install channels. Part-delivery messages say that remaining items are still outstanding.

Jobs Overview shows all permitted jobs. Filter quotes/sales orders; use Photos for images. Quotes enter after Site Visit or Quote Review is requested. Omni's strip shows the current job.

Corrections, colours & everyday checks

What to expect when a job changes, and what is not automatic.

Part delivered is not dispatched

Workflow records Part Delivered and can send a WeCom part-delivery message. Outstanding goods prevent full dispatch and completion. There is no separate Part Delivered HubSpot stage; the current stage is retained.

A green Packed dot is not a green card

Omni Fully Packed turns the packing indicator green. Delivery-card readiness shading requires Paid + In Stock + Packed together. HubSpot readiness uses paid + packed + a goods card, so these two visual rules are not identical.

Undo an accidental completion

Explicitly reversing delivered/collected or install/confirmation actions records a correction. HubSpot can then return to the applicable readiness or payment stage. A goods reversal can also clear Omni's dispatch date and restore the appropriate warehouse stage on the open order.

Ordinary refreshes do not move later-stage deals backwards.

Hold, New & freight changes

On Hold returns collection work to the queue and clears collection completion. An explicit New/queue correction also returns HubSpot to Paid or Part Paid using saved payment data.

Changing freight moves unfinished goods work between Delivery and Collect. Completed/part-delivered records may remain as history.

Site visits & quote reviews

Jobs Overview shows Booked, Confirmed or Completed from the saved visit status. Checklist measurements are optional. Completed jobs archive visits, retaining history and stats.

Review approval is not a separate HubSpot trigger. Completing/removing the last active visit releases its temporary stage to the applicable payment/waiting stage.

Installation scheduling warnings

Delivery booked after the linked install date turns the delivery card's Install link red. Installation confirmation needs the team tick and any enabled, required Sales tick. Assembly/installation prevents goods delivery alone from completing the HubSpot deal.

Payment corrections & sign-off

Full-to-part payment returns HubSpot to Part Paid. Removing payment returns it to Wait On Customer unless an active site visit applies. Saved delivery/install history remains; Closed deals stay closed.

Jobs Overview also checks balance owing and install sign-off. Save customer sign-off before treating installation as fully finished.

Save, refresh & check the right source

Save Omni edits and wait for Workflow to show Saved. Visible progress/card lookups run about every 2-3 seconds; background sync is not instant. Resolve unsaved-change warnings before leaving.

HubSpot edits do not rewrite Omni or Workflow. Use Report Issue for operational or system errors, checking the prefilled customer/NZSO.

If the three views appear to disagreeCheck the exact NZSO → save Omni → check payment, goods and install cards → allow the sync to finish → inspect Jobs Overview / the HubSpot sync report. Missing or ambiguous HubSpot stage/deal matches are reported instead of guessed. Payment Send to WeCom saves and verifies the payment first.
